ETAPA 01

Minimundo e Regras de Negócio da Plataforma

Definição do escopo operacional, atores envolvidos, entidades fundamentais e restrições de integridade que regem o ecossistema do aplicativo de streaming musical.

📖 Descrição do Minimundo (App de Streaming de Música)

Visão Geral do Domínio

O sistema modelado contempla a infraestrutura de dados para um serviço moderno de Streaming de Música Digital sob demanda. A plataforma permite que ouvintes acessem um vasto catálogo fonográfico, assinem planos mensais ou anuais, criem seleções personalizadas de faixas e interajam diretamente com a discografia de seus artistas prediletos.

O ecossistema é alicerçado na gestão de Usuários, que contratam Planos de Assinatura (como Individual, Familiar ou Universitário) e geram Pagamentos recorrentes. Do ponto de vista fonográfico, o catálogo é catalogado por Gêneros Musicais, Artistas cadastrados e seus respectivos Álbuns de estúdio, que reúnem múltiplas Músicas (Faixas) com metadados como duração, data de lançamento e taxa de amostragem.

A experiência interativa do ouvinte consolida-se através da criação e curadoria de Playlists (tanto públicas quanto privadas), marcação de faixas favoritas (Curtidas), acompanhamento de perfis (Seguidores de Artista) e o rastreamento em tempo real de cada reprodução via Histórico de Reprodução, viabilizando métricas precisas de faturamento e royalties.

⚖️ Regras de Negócio (RN)

Restrições & Políticas
  1. RN01 - Unicidade de Cadastro: Todo usuário deve possuir endereço de e-mail e CPF cadastrados sob restrição de unicidade (UNIQUE) e formato válido.
  2. RN02 - Vinculação Obrigatória a Plano: Ao criar uma conta, o usuário deve obrigatoriamente estar associado a um plano de assinatura ativo (gratuito ou pago).
  3. RN03 - Histórico Financeiro: Cada transação de pagamento deve registrar data, valor monetário, método de liquidação e status (Pendente, Aprovado, Estornado).
  4. RN04 - Integridade do Catálogo Musical: Toda música deve estar estritamente vinculada a um álbum existente e associada a um gênero musical previamente homologado.
  5. RN05 - Autoria de Álbuns e Músicas: Um álbum pertence a um único artista principal, herdando a nacionalidade e os identificadores oficiais do artista cadastrado.
  6. RN06 - Relacionamento Playlist-Músicas: Uma playlist pode comportar inúmeras músicas e a mesma música pode estar em diversas playlists (relação N:M resolvida via tabela associativa com ordem de reprodução).
  7. RN07 - Auditoria de Reprodução: Cada reprodução realizada dispara um registro de log no histórico com timestamp (data/hora exata) e percentual consumido da faixa.
  8. RN08 - Não-Duplicação de Curtidas: Um usuário só pode curtir uma mesma música uma única vez, sendo garantida a integridade por chave primária composta (ID_Usuario + ID_Musica).

Scripts SQL (DDL & DML — MyCompiler)

Comandos padronizados em SQL ANSI executados e validados no compilador online MyCompiler para a criação estrutural, instanciação e definição de integridade referencial.

Script 01 — Criação das Tabelas (DDL: CREATE TABLE) DDL
01_create_tables_ddl.sql [SQL / MyCompiler] 
-- ==========================================================
-- PROJETO: BANCO DE DADOS DE STREAMING MUSICAL
-- ARQUIVO: 01_create_tables_ddl.sql
-- AMBIENTE DE EXECUÇÃO: MyCompiler (MySQL / MariaDB)
-- ==========================================================

-- 1. TABELA DE PLANOS DE ASSINATURA
CREATE TABLE tb_planos (
    id_plano INT AUTO_INCREMENT PRIMARY KEY,
    nome_plano VARCHAR(50) NOT NULL,
    valor_mensal DECIMAL(10,2) NOT NULL,
    limite_dispositivos INT DEFAULT 1,
    qualidade_audio VARCHAR(30) NOT NULL
);

-- 2. TABELA DE USUÁRIOS
CREATE TABLE tb_usuarios (
    id_usuario INT AUTO_INCREMENT PRIMARY KEY,
    nome_completo VARCHAR(120) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE,
    data_nascimento DATE NOT NULL,
    id_plano INT NOT NULL,
    status_conta VARCHAR(20) DEFAULT 'Ativo'
);

-- 3. TABELA DE PAGAMENTOS
CREATE TABLE tb_pagamentos (
    id_pagamento INT AUTO_INCREMENT PRIMARY KEY,
    id_usuario INT NOT NULL,
    data_pagamento TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    valor_pago DECIMAL(10,2) NOT NULL,
    metodo_pagamento VARCHAR(40) NOT NULL,
    status_transacao VARCHAR(20) DEFAULT 'Aprovado'
);

-- 4. TABELA DE GÊNEROS MUSICAIS
CREATE TABLE tb_generos (
    id_genero INT AUTO_INCREMENT PRIMARY KEY,
    nome_genero VARCHAR(50) NOT NULL UNIQUE,
    descricao VARCHAR(255)
);

-- 5. TABELA DE ARTISTAS
CREATE TABLE tb_artistas (
    id_artista INT AUTO_INCREMENT PRIMARY KEY,
    nome_artistico VARCHAR(100) NOT NULL,
    pais_origem VARCHAR(50),
    ouvintes_mensais INT DEFAULT 0,
    verificado BOOLEAN DEFAULT FALSE
);

-- 6. TABELA DE ÁLBUNS
CREATE TABLE tb_albuns (
    id_album INT AUTO_INCREMENT PRIMARY KEY,
    titulo_album VARCHAR(120) NOT NULL,
    ano_lancamento INT NOT NULL,
    id_artista INT NOT NULL,
    gravadora VARCHAR(80),
    tipo_lancamento VARCHAR(30) DEFAULT 'Álbum de Estúdio'
);

-- 7. TABELA DE MÚSICAS (FAIXAS)
CREATE TABLE tb_musicas (
    id_musica INT AUTO_INCREMENT PRIMARY KEY,
    titulo_musica VARCHAR(120) NOT NULL,
    duracao_segundos INT NOT NULL,
    id_album INT NOT NULL,
    id_genero INT NOT NULL,
    faixa_numero INT NOT NULL
);

-- 8. TABELA DE PLAYLISTS
CREATE TABLE tb_playlists (
    id_playlist INT AUTO_INCREMENT PRIMARY KEY,
    nome_playlist VARCHAR(100) NOT NULL,
    descricao VARCHAR(255),
    id_usuario INT NOT NULL,
    publica BOOLEAN DEFAULT TRUE,
    data_criacao DATE NOT NULL
);

-- 9. TABELA ASSOCIATIVA PLAYLIST-MÚSICA (N:M)
CREATE TABLE tb_playlist_musica (
    id_playlist INT NOT NULL,
    id_musica INT NOT NULL,
    ordem_execucao INT NOT NULL,
    adicionado_em TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id_playlist, id_musica)
);

-- 10. TABELA DE HISTÓRICO DE REPRODUÇÃO
CREATE TABLE tb_historico_reproducao (
    id_reproducao INT AUTO_INCREMENT PRIMARY KEY,
    id_usuario INT NOT NULL,
    id_musica INT NOT NULL,
    data_hora_reproducao TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    segundos_ouvidos INT NOT NULL,
    dispositivo VARCHAR(50)
);

-- 11. TABELA DE CURTIDAS (FAVORITAS)
CREATE TABLE tb_curtidas (
    id_usuario INT NOT NULL,
    id_musica INT NOT NULL,
    data_curtida TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (id_usuario, id_musica)
);

-- 12. TABELA DE SEGUIDORES DE ARTISTAS
CREATE TABLE tb_seguidores_artista (
    id_usuario INT NOT NULL,
    id_artista INT NOT NULL,
    data_seguindo TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    notificacoes_ativas BOOLEAN DEFAULT TRUE,
    PRIMARY KEY (id_usuario, id_artista)
);

ETAPA 05

Queries de Pesquisa e Retorno de Dados (DQL)

Demonstração de consultas analíticas e relacionais com junções (JOIN), agregações (COUNT, SUM) e ordenações para validação em sala de aula.

Consulta 01 — Listar usuários ativos e seus respectivos planos (INNER JOIN) INNER JOIN
query_01_usuarios_planos.sql [SELECT / DQL] 
SELECT 
    u.id_usuario,
    u.nome_completo AS usuario,
    u.email,
    p.nome_plano AS plano,
    p.valor_mensal AS mensalidade,
    p.qualidade_audio
FROM tb_usuarios u
INNER JOIN tb_planos p ON u.id_plano = p.id_plano
WHERE u.status_conta = 'Ativo'
ORDER BY u.nome_completo ASC;

Consulta 02 — Top 5 músicas mais reproduzidas na plataforma (GROUP BY + COUNT + ORDER BY) GROUP BY & COUNT
query_02_top_reproduzidas.sql [SELECT / DQL] 
SELECT 
    m.id_musica,
    m.titulo_musica,
    a.nome_artistico AS artista,
    COUNT(h.id_reproducao) AS total_reproducoes
FROM tb_musicas m
INNER JOIN tb_albuns alb ON m.id_album = alb.id_album
INNER JOIN tb_artistas a ON alb.id_artista = a.id_artista
LEFT JOIN tb_historico_reproducao h ON m.id_musica = h.id_musica
GROUP BY m.id_musica, m.titulo_musica, a.nome_artistico
ORDER BY total_reproducoes DESC
LIMIT 5;

Consulta 03 — Buscar todas as faixas de uma Playlist específica com nome do Artista e Álbum MULTI JOIN

SELECT 
    p.nome_playlist,
    pm.ordem_execucao AS ordem,
    m.titulo_musica,

Consulta 04 — Relatório de faturamento por tipo de plano de assinatura (SUM + GROUP BY) SUM & FINANCEIRO
query_04_faturamento_planos.sql [SELECT / DQL] 
SELECT 
    p.id_plano,
    p.nome_plano,
    COUNT(DISTINCT u.id_usuario) AS assinantes_ativos,
    COALESCE(SUM(pag.valor_pago), 0.00) AS faturamento_total_bruto
FROM tb_planos p
LEFT JOIN tb_usuarios u ON p.id_plano = u.id_plano AND u.status_conta = 'Ativo'
LEFT JOIN tb_pagamentos pag ON u.id_usuario = pag.id_usuario AND pag.status_transacao = 'Aprovado'
GROUP BY p.id_plano, p.nome_plano
ORDER BY faturamento_total_bruto DESC;

ETAPA 01

Minimundo e Regras de Negócio da Plataforma

Definição do escopo operacional, atores envolvidos, entidades fundamentais e restrições de integridade que regem o ecossistema do aplicativo de streaming musical.

📖 Descrição do Minimundo (App de Streaming de Música)

Visão Geral do Domínio

O sistema modelado estrutura o banco de dados de uma nova plataforma de Streaming Musical, criada para competir com os serviços já consolidados no mercado. A aplicação permite que os usuários busquem músicas com facilidade, montem listas personalizadas, acompanhem seus artistas favoritos e assinem diferentes planos de acesso.

A base do sistema organiza o cadastro de Usuários e seus respectivos Planos de Assinatura, garantindo o controle dos pagamentos e acessos. No catálogo, as Músicas e os Artistas são registrados com informações detalhadas, o que agiliza as buscas e serve de base para o sistema sugerir novas faixas de acordo com o gosto de cada pessoa.

Para tornar a experiência mais interativa, o projeto contempla a criação de Playlists, a opção de seguir perfis de artistas e o registro contínuo do Histórico de Reprodução. Com esses dados organizados, a plataforma consegue entender o comportamento dos ouvintes, melhorar as recomendações e acompanhar o uso geral do serviço.

⚖️ Regras de Negócio (RN)

Restrições & Políticas
  1. RN01 - Participação múltipla de artistas: Um Artista não fica limitado a uma única faixa, podendo participar da gravação e produção de várias Músicas dentro do catálogo da plataforma.
  2. RN02 - Agrupamento de faixas por álbum: Cada Álbum cadastrado funciona como um agrupador do acervo, podendo conter diversas Músicas vinculadas a um mesmo projeto ou lançamento.
  3. RN03 - Colaborações e parcerias musicais: Para contemplar parcerias e colaborações musicais, uma mesma Música pode estar associada a mais de um Artista participante.
  4. RN04 - Criação ilimitada de playlists: O sistema oferece liberdade de organização ao ouvinte, permitindo que um mesmo Usuário crie e gerencie diversas Playlists personalizadas em sua conta.
  5. RN05 - Composição múltipla de playlists: Uma Playlist atua como uma lista flexível de reprodução, podendo reunir diversas Músicas escolhidas e ordenadas pelo usuário.
  6. RN06 - Reutilização de faixas em coleções: As faixas do catálogo são reutilizáveis nas coleções, o que permite que uma mesma Música seja adicionada a diferentes Playlists simultaneamente.
  7. RN07 - Registro contínuo de reproduções: Para alimentar as métricas de uso e recomendações, cada Usuário acumula um Histórico de Reprodução com o registro de várias faixas ouvidas ao longo do tempo.

ETAPA 04

Scripts SQL (DDL & DML — MyCompiler)

Comandos padronizados em SQL ANSI executados e validados no compilador online MyCompiler para a criação estrutural, instanciação e definição de integridade referencial.

Script 01 — Criação das Tabelas (DDL: CREATE TABLE) DDL
01_create_tables_ddl.sql [SQL / MyCompiler] 
-- ==========================================================
-- PROJETO: BANCO DE DADOS DE STREAMING MUSICAL (db_server_music)
-- ARQUIVO: 01_create_tables_ddl.sql
-- AMBIENTE DE EXECUÇÃO: MyCompiler (MySQL / MariaDB)
-- ==========================================================

DROP DATABASE IF EXISTS db_server_music;
CREATE DATABASE db_server_music;
USE db_server_music;

CREATE TABLE users (
	id_user INT AUTO_INCREMENT PRIMARY KEY,
	nome VARCHAR(100) NOT NULL,
	cpf VARCHAR(11) NOT NULL UNIQUE,
	email VARCHAR(200) NOT NULL UNIQUE,
	senha VARCHAR(200) NOT NULL,
	cep VARCHAR(8) NOT NULL,
	rua VARCHAR(100) NOT NULL,
	numero INT NOT NULL,
	cidade VARCHAR(50) NOT NULL,
	bairro VARCHAR(50) NOT NULL
);

CREATE TABLE planos (
    id_plano INT AUTO_INCREMENT PRIMARY KEY,
    tipo VARCHAR(100) UNIQUE,
    valor DECIMAL(5, 2),
    qtn_users INT DEFAULT 0
);

CREATE TABLE pagamentos (
    id_pagamento INT AUTO_INCREMENT PRIMARY KEY,
    forma_de_pagamento VARCHAR(20),
    timestamp DATETIME,
    id_user INT,
    CONSTRAINT fk_id_user FOREIGN KEY (id_user)
        REFERENCES users (id_user),
    id_plano INT,
    CONSTRAINT fk_id_plano FOREIGN KEY (id_plano)
        REFERENCES planos (id_plano),
    status_pagamento INT NOT NULL
);

CREATE TABLE telefones (
    id_tel INT AUTO_INCREMENT NOT NULL PRIMARY KEY,
    tel VARCHAR(11) NOT NULL,
    id_user INT,
    CONSTRAINT fk_id_user_tel FOREIGN KEY (id_user)
        REFERENCES users (id_user)
    ON DELETE CASCADE
    ON UPDATE CASCADE
);

CREATE TABLE generos (
    id_genero INT AUTO_INCREMENT NOT NULL PRIMARY KEY,
    nome VARCHAR(100) UNIQUE,
    desc_genero VARCHAR(300)
);

CREATE TABLE artistas (
    id_art INT AUTO_INCREMENT NOT NULL PRIMARY KEY,
    nome VARCHAR(80) NOT NULL,
    email VARCHAR(100) NOT NULL UNIQUE,
    senha VARCHAR(100) NOT NULL,
    nacionalidade VARCHAR(50)
);

CREATE TABLE albuns (
    id_album INT AUTO_INCREMENT NOT NULL PRIMARY KEY,
    nome VARCHAR(80) NOT NULL,
    qnt_musica INT DEFAULT 0,
    data_de_criacao DATE,
    id_art INT,
    CONSTRAINT fk_id_art FOREIGN KEY (id_art)
        REFERENCES artistas (id_art)
);

CREATE TABLE musicas (
    id_musica INT AUTO_INCREMENT NOT NULL PRIMARY KEY,
    nome VARCHAR(80) NOT NULL,
    duracao_secs INT NOT NULL,
    id_album INT,
    id_genero INT,
    CONSTRAINT fk_id_album FOREIGN KEY (id_album)
        REFERENCES albuns (id_album),
    CONSTRAINT fk_genero FOREIGN KEY (id_genero)
        REFERENCES generos (id_genero)
);

CREATE TABLE historicos (
    id_historico INT AUTO_INCREMENT PRIMARY KEY,
    id_user INT,
    id_album INT,
    id_musica INT,
    reg_time DATETIME,
    CONSTRAINT fk_id_user_hist FOREIGN KEY (id_user)
        REFERENCES users (id_user),
    CONSTRAINT fk_id_musica_hist FOREIGN KEY (id_musica)
        REFERENCES musicas (id_musica),
    CONSTRAINT fk_id_albun_hist FOREIGN KEY (id_album)
        REFERENCES albuns (id_album)
);

CREATE TABLE playlists (
    id_playlist INT AUTO_INCREMENT NOT NULL PRIMARY KEY,
    nome VARCHAR(80) NOT NULL,
    desc_playlist VARCHAR(1000),
    is_public INT DEFAULT 0,
    data_criacao DATETIME,
    id_user INT,
    CONSTRAINT fk_id_user_play FOREIGN KEY (id_user)
        REFERENCES users (id_user)
);

CREATE TABLE playlist_assoc (
    id_playlist_assoc INT AUTO_INCREMENT PRIMARY KEY,
    id_playlist INT,
    id_musica INT,
    UNIQUE KEY uk_playlist_musica (id_playlist, id_musica),
    CONSTRAINT fk_id_playlist FOREIGN KEY (id_playlist)
        REFERENCES playlists (id_playlist),
    CONSTRAINT fk_id_musica_assoc FOREIGN KEY (id_musica)
        REFERENCES musicas (id_musica)
);

CREATE TABLE art_music_assoc (
    id_art_music_assoc INT AUTO_INCREMENT NOT NULL PRIMARY KEY,
    id_art INT,
    id_musica INT,
    CONSTRAINT fk_id_art_assoc FOREIGN KEY (id_art)
        REFERENCES artistas (id_art),
    CONSTRAINT fk_musica_assoc FOREIGN KEY (id_musica)
        REFERENCES musicas (id_musica)
);

Consulta 02 — Consultas Analíticas: Pagamentos Concluídos, Histórico, Contagem e Agrupamento SELECT / DQL
query_02_consultas_analiticas.sql [SELECT / MyCompiler] 
SELECT u.nome, p.id_user FROM pagamentos AS p INNER JOIN users AS u ON u.id_user = p.id_user WHERE status_pagamento = 0;

SELECT id_user, id_musica, reg_time FROM historicos ORDER BY reg_time; 

SELECT COUNT(id_plano) FROM pagamentos WHERE status_pagamento = 0 AND id_plano = 2;

SELECT COUNT(cidade) FROM users GROUP BY cidade;
